## How to run (Postman CLI)

Run the **local copy** with a **logged-out** Postman CLI (`postman whoami` shows no account, `POSTMAN_API_KEY` not set) and from a folder outside the repo. A run by cloud uid, or any run while logged in, is uploaded to Postman Cloud with request bodies; `--no-report-events` does not stop that (CLI 1.87.0, run `…-2026-11-09-0123` of API-OP-005; the 2026-11-09 run in [Runs](#runs) above was uploaded the same way). `baseUrl` (from `Skypermit-vercel`) goes in with `--env-var` instead of `-e`. Secrets come from environment variables of the shell, never from the command text itself. The usual way is the `postman-cli-run` skill, which checks all of this before it runs.

```bash
# bash (from a folder outside the repo)
export SKY_OPERATOR_PASSWORD='...'   # min 8 chars
postman collection run "<absolute path to repo>/postman/SKY-2/TC-GATE-001.postman_collection.json" \
  --env-var "baseUrl=https://skypermit.vercel.app/api/v1" \
  --env-var "operatorPassword=$SKY_OPERATOR_PASSWORD" \
  --no-report-events
```

```powershell
# PowerShell (from a folder outside the repo)
$env:SKY_OPERATOR_PASSWORD = '...'   # min 8 chars
postman collection run "<absolute path to repo>\postman\SKY-2\TC-GATE-001.postman_collection.json" --env-var "baseUrl=https://skypermit.vercel.app/api/v1" --env-var "operatorPassword=$env:SKY_OPERATOR_PASSWORD" --no-report-events
```

Pass one `--env-var "<name>=<value>"` per non-secret variable and per secret variable of the environment.
